Which approach should we take?

All three land at the same premium visual quality — the question is sequencing and risk.

A

Chart Primitives First

Build shared SVG chart components (BarChart, LineChart, DonutChart, BranchingPath) as a reusable library, then wire each slide template to them. Every future template automatically gets data visualization capability.

Pros

  • Most extensible foundation
  • Each primitive is testable in isolation
  • AI payload drives the chart data cleanly

Cons

  • Longer before first visible result
  • More upfront design decisions
B

Template-by-Template Upgrade RECOMMENDED

Upgrade each slide template individually — starting with CashflowSlide and CoverSlide since they appear in the reference images. Extract shared patterns into primitives as they emerge naturally.

Pros

  • Fast visible progress (first template ships quickly)
  • Primitives emerge from real usage, not speculation
  • Lower risk — each template is independently deployable

Cons

  • Some duplication across early templates before patterns solidify
C

Full Visual Overhaul at Once

Redesign all 10 existing templates simultaneously, enforcing the new design language across the entire system in a single coordinated pass.

Pros

  • Maximum consistency from day one
  • No visual debt between templates

Cons

  • High blast radius — one bad template breaks the whole set
  • Long before anything is shippable
  • Hard to iterate on design decisions mid-flight
